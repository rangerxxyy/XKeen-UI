# Правила работы над XKeen UI

- Основной продуктовый код: TypeScript 60–65%, Rust 30–32%, POSIX Shell 2–3% (ориентир по собственным строкам исходного кода; generated/vendor исключаются).
- Перед изменением проверять рабочее дерево и сохранять пользовательские данные. Не удалять пользовательские настройки, профили, бэкапы или существующие реализации без необходимости.
- UI не должен выдумывать статус служб, DNS-ответы, группы, подключения или результаты проверок. Нет источника данных — показывать отсутствие данных и причину.
- Все управляющие действия над роутером должны иметь явный сценарий подтверждения, проверку входных данных, журнал без секретов, резервное копирование и документированный откат.
- Не выполнять реальные изменения DNS, маршрутизации, firewall, ядра или конфигурации роутера в локальном simulation mode.
- Ограничивать файловые операции заранее заданными корнями, проверять символические ссылки и атомарно заменять файлы после проверки.
- Не открывать API управления в сеть без аутентификации и проверки origin/CSRF для изменяющих запросов.
- Внешние XKeen UI — источники наблюдений. Не копировать код и не воспроизводить интерфейс пиксель в пиксель.
- Не объявлять функцию, тест, совместимость, визуальную проверку или релиз завершёнными без воспроизводимого результата.
- После значимого этапа обновлять PLAN.md, PROJECT_STATUS.md и относящиеся к нему документы.
