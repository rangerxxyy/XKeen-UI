## Следующий крупный этап: v4.0

До реализации сверять каждый пункт с сообщениями и скриншотами пользователя, контрактами текущего backend и публичным `zxc-rv/XKeen-UI`. На дату аудита upstream не изменился с `4ffd568eac2ad666a11730e6eaeb1c6b1ecc16bd` / `v1.3.8`.

### Приоритет 0 — безопасность и восстановление

- [ ] Реализовать настоящее серверное управление доступом с входом, безопасным хешированием пароля, ограничением попыток, истечением/отзывом сессии и защитой всех API-данных и операций. Не выдавать браузерную блокировку интерфейса за защиту API.
- [ ] Сохранять и восстанавливать DNS-транзакции без потери исходных серверов, DoH/DoT и настроек фильтра; при частичном сбое оставлять видимый recovery-снимок и безопасный повтор.
- [ ] Сформировать threat model для режима привязки к LAN, reverse proxy, CSRF, XSS и секретов; тестировать по умолчанию без доступа к реальному роутеру.

### Приоритет 1 — надёжность конфигурации и диагностики

- [ ] Проверить, что Mihomo и Xray используют корректные версии валидатора, резервное копирование, атомарную запись и подтверждённый откат; явно показывать ограничения Xray multi-file apply.
- [ ] Расширить тестирование импорта прокси для каждого поддержанного формата и гарантировать безопасную обработку секретов в preview, журналах и ошибках.
- [ ] Проверить селекторы, соединения, providers и DNS на моделях API и деградацию при недоступности ядра; не считать тесты с mock ответами подтверждением работы на роутере.

### Отложено до отдельного проектирования

Geo scan, полный route tester, HTTP-предпросмотр подписок, multi-router/plugin configuration, управление DNS Xray и полная обратимость контент-фильтра. Для каждого нужны отдельная спецификация, лимиты ресурсов и явное описание побочных эффектов.
