# Состояние проекта

## Версия 0.1.0 — первый вертикальный срез

- Добавлены TypeScript UI, Rust API и POSIX Shell installer scaffold.
- API по умолчанию использует порт 1001.
- Simulation mode изолирован от системных процессов и настроек роутера.
- Показатели ОС читаются только из `/proc`, `/proc/meminfo` и `/proc/loadavg`. Отдельные Mihomo API действия позволяют переключить Selector и закрывать соединения после явного подтверждения; файловые и системные настройки роутера текущий backend не меняет.
- Router mode требует сгенерированный установщиком 256-битный bearer token для API. UI хранит его в `sessionStorage` только в текущей вкладке.
- Конфигурация получила CodeMirror-вкладки `config`, `ip_exclude`, `port_exclude`, `port_proxying`, `xkeen`, `Xray JSON`, `Xray JSONC`: раздельные черновики в `sessionStorage`, экспорт выбранного файла, YAML 1.2-проверка и форматирование для `config`, JSON/JSONC syntax check и форматирование для Xray. Проверка схем ядер, чтения/применения файлов на роутере нет.
- Реализованы подключения к локальному Mihomo Clash API для чтения версии, proxy-групп, соединений и правил; UI показывает proxy selector cards, список соединений и их маршруты/трафик, а также фильтр соединений.
- Переключение selector и закрытие одного/всех соединений доступны как изменяющие операции; интерфейс явно подтверждает действия, backend требует bearer-токен и строгий same-origin `Origin`/`Host`, закрытие одного соединения перепроверяет активность ID. Эти операции не запускались против пользовательского роутера.
- Добавлен read-only DNS lookup через локальный Mihomo API: валидация домена и типа записи на backend, запрос только по действию пользователя, отображение статуса и Answer. Настройки DNS и Xray DNS, логи, резервирование/безопасное применение/откат конфигурации и управление Xray остаются не реализованы.
- Добавлены read-only списки Mihomo proxy/rule providers. В редактор подключён выбор двух Mihomo YAML и семи Xray JSON-шаблонов из закреплённой ревизии `zxc-rv/assets`; импорт меняет только вкладочный черновик.
- Передачу системного DNS Mihomo нельзя считать реализованной: upstream-отключение не восстанавливает исходные DNS/DoH/DoT, а контентный фильтр и снимок его состояния там не обрабатываются. До проектирования полного mock-транзакционного отката RCI-переключатель отсутствует.
- Исходный HTML-шаблон удалён; Vite генерирует минимальный документ при сборке, UI и стили принадлежат TypeScript/CSS. Собранный `release/web/index.html` остаётся runtime-оболочкой для браузера и backend ServeDir.
- Backend требует router bearer token; изменяющие endpoints дополнительно требуют Origin, совпадающий с Host и портом. Полноценное управление учётными записями, CSRF token и работа через reverse proxy не реализованы.
- Целевая среда подтверждена на роутере: KeeneticOS/Entware, AArch64, glibc 2.27.
- Тестовый AArch64-бинарник собран в CI с Entware dynamic loader (`/opt/lib/ld-linux-aarch64.so.1`) и успешно проверен на устройстве на loopback-порту 18473: `/health`, отказ API без bearer-токена, read-only status с токеном и раздача frontend.
- После проверки тестовый процесс остановлен, временный каталог `/tmp/xkeen-ui-test-…` удалён. Существующие службы и файлы Entware не менялись.
- Репозиторий опубликован на GitHub. README удалён по просьбе пользователя, release и публичная инструкция установки не публиковались. CI-артефакт сборки предназначен только для проверки.
- Installer прошёл ShellCheck и синтаксическую проверку, но его установка и управление службой на устройстве не проверялись.

## Среда

- Доступны Git, GitHub CLI, Node.js и pnpm workspace runtime.
- Локальная Windows-среда не содержит Rust/MSVC linker; Rust format, tests и build выполняются в GitHub Actions.
- Последний CI запуск выявил форматирование Rust и отсутствующий импорт константы заголовка в AArch64 сборке; оба исправления внесены. Следующий GitHub Actions запуск должен подтвердить frontend typecheck/build, Rust fmt/tests/build, POSIX shell/ShellCheck и AArch64 Entware cross-build. Локально frontend typecheck/build проходят; cargo недоступен в PATH.
- Аудит структуры и исходников двух референсов собран в `docs/REFERENCE_AUDIT.md`; на устройстве проверена только read-only связность backend и выдача UI.

## Следующие шаги

1. Проверить DNS lookup и новые Rust изменения в CI; проверить DNS только на mock или после отдельного безопасного согласования, не на пользовательском роутере.
2. Добавить mock-интеграционные проверки Mihomo API и закрытия соединений; проверить origin guards без вызова реального роутера.
3. Зафиксировать фактические API и расположение конфигураций Mihomo/Xray без изменений на устройстве.
4. Реализовать отдельными вертикальными срезами настройки DNS, логи, управление версиями и безопасную работу с конфигурацией; подтвердить контракты до подключения реального изменения состояния.
5. Для каждого изменения на роутере сначала подготовить план отката и ограничить операции тестовым окружением.
6. Перед публикацией install release отдельно согласовать готовность пользовательской установки; до этого не создавать release-артефакты.
