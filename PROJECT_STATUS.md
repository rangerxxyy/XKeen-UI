# Состояние проекта

## Состояние разработки

- Добавлены TypeScript UI, Rust API и компактный POSIX Shell bootstrap. В текущей ветке lifecycle install/update/remove и служба переносятся в Rust.
- API по умолчанию использует порт 1001.
- Simulation mode изолирован от системных процессов и настроек роутера.
- Показатели ОС читаются только из `/proc`, `/proc/meminfo` и `/proc/loadavg`. Отдельные Mihomo API действия позволяют переключить Selector и управлять соединениями. Файловые и системные операции роутера доступны только в router mode и сериализуются с изменениями ядра.
- Router mode требует сгенерированный установщиком 256-битный bearer token для API. UI хранит его в `sessionStorage` только в текущей вкладке.
- Конфигурация получила CodeMirror-вкладки `config`, `ip_exclude`, `port_exclude`, `port_proxying`, `xkeen`, `Xray JSON`, `Xray routing`: раздельные черновики в `sessionStorage`, стартовые шаблоны Mihomo/Xray «Только заблокированное», выбор второго шаблона «Всё через PROXY, кроме RU», экспорт, проверка YAML 1.2/JSONC и форматирование. На роутере сетевые списки и `xkeen.json` считываются из штатных файлов; сохранение делает проверку содержимого и резервную копию. Mihomo config можно проверить ядром, сохранить с резервом и откатить при неудачном рестарте.
- Реализованы подключения к локальному Mihomo Clash API для чтения версии, proxy-групп, соединений и правил; UI показывает proxy selector cards, список соединений и их маршруты/трафик, а также фильтр соединений.
- Переключение Selector выполняется без системного браузерного предупреждения. Для закрытия соединений, замены черновика и установки релизов подтверждение показывается внутри панели; браузерный `window.confirm()` удалён. Backend требует bearer-токен и строгий same-origin `Origin`/`Host`, закрытие соединения перепроверяет активность ID.
- Добавлен read-only DNS lookup через локальный Mihomo API: валидация домена и типа записи на backend, запрос только по действию пользователя, отображение статуса и Answer. Вкладка «Управление» показывает состояния DNS KeeneticOS/Mihomo и владельца порта 53, с подтверждением включает передачу IPv4 DNS и сохраняет прежние статические DNS-серверы для возврата.
- Добавлены read-only списки Mihomo proxy/rule providers. Встроенные стартовые шаблоны основаны на закреплённой ревизии `zxc-rv/assets`; выбор шаблона работает офлайн и меняет только черновик. Другие upstream-шаблоны могут загружаться по запросу.
- В ⚙ добавлена вкладка «Источники ядер» для отдельных GitHub URL Xray/Mihomo: backend проверяет owner/repo и сохраняет настройки приложения с ограниченными правами; frontend читает опубликованные GitHub-релизы и показывает совместимые ARM64-архивы. Rust updater проверяет допустимый GitHub asset, SHA-256 и ELF/AArch64, ограничивает архив, делает резервную копию, проверяет активный конфиг до атомарной замены и откатывает неудачный запуск. Функция включена в стабильный v0.2.1, но на активных пользовательских ядрах не запускалась.
- Продолжение работы над обновлением: оригинальный MetaCubeX Mihomo остаётся источником по умолчанию, добавлены пресет Prizrak-Core и произвольный GitHub-форк; выбор сохраняет источник отдельно и не устанавливает/переключает ядро. Список релизов скрывает prerelease и версии без совместимого ARM64 asset. Кнопка установки обновления XKeen UI запускает штатный `install.sh update`; header получает CPU % из двух снимков `/proc/stat`. Frontend: 68 тестов и production build прошли; backend Rust fmt/test и роутерная сборка ожидают CI, так как локально нет Rust/Cargo. На устройстве проверялась только загрузка релизов; бинарники ядер не менялись.
- Управление службой XKeen доступно через окно состояния сервисов в верхней панели: старт/рестарт/стоп показываются в router mode и требуют подтверждения. Backend принимает только найденный штатный Entware init-файл, ограничивает команду 30 секундами, не ждёт унаследованные daemon stdout/stderr и подтверждает реальное состояние процесса. Stop блокируется, пока KeeneticOS передаёт DNS через XKeen.
- Панель имеет четыре раздела в порядке «Селекторы → Соединения → Конфигурация → DNS». Журнал размещён под прокручиваемой рабочей областью без отдельной вкладки. Оформление переведено на матовую тёмную сине-фиолетовую палитру.
- Для журнала добавлен read-only endpoint с фиксированным allowlist `/opt/var/log`, максимумом 256 KiB и 1000 строк, фильтром и расширенным просмотром в UI; вывод использует `textContent`, параметры секретов в строках редактируются. Кнопка очистки очищает только окно интерфейса. CI прошёл для commit `947b902`; содержимое системных журналов на пользовательском роутере не просматривалось.
- DNS управление Mihomo имеет отдельную вкладку: статус читает DNS Override, статические IPv4/IPv6 nameserver, активный YAML и владельца порта 53; перед передачей UI требует явное подтверждение, backend валидирует кандидат установленным Mihomo и сохраняет прежние статические DNS с rollback. IPv4-серверы временно заменяются адресом роутера, статические IPv6-серверы сохраняются и могут обходить Mihomo. При возврате DNS Keenetic восстанавливается до отключения DNS Mihomo. Stop XKeen и изменение ядра блокируются, пока DNS Override активен; применение конфига проверяет, что DNS Mihomo и слушатель `0.0.0.0:53` сохраняются. Реальная передача DNS на роутере не выполнялась; DoH/DoT и фильтр контента не сохраняются и не восстанавливаются.
- Управление XKeen start/stop/restart переведено на штатный init-скрипт; backend ждёт подтверждённого состояния и сериализует операцию с DNS/core update lock. Шапка показывает подтверждённое состояние и занятое действие. Новая сборка ещё не поставлена на пользовательский роутер.
- Список подключений отображается компактными адаптивными карточками с иконкой сервиса и отдельными строками маршрута, устройства, протокола, трафика и времени; минимальная ширина карточки снижена, чтобы на обычной ширине панели помещалось больше потоков.
- Исходный HTML-шаблон удалён; Vite генерирует минимальный документ при сборке, UI и стили принадлежат TypeScript/CSS. Собранный `release/web/index.html` остаётся runtime-оболочкой для браузера и backend ServeDir.
- Установочное меню стилизовано по композиции `setup.sh` zxc-rv: ASCII-знак перекрашен в фиолетовый и сопровождается отчётливой подписью `XKeen  UI`; архитектура и статус подсвечены бирюзовым, интерактивное меню очищает экран. Bootstrap использует тихий curl и прямой URL релиза по tag; после распаковки явно восстанавливает executable-бит бинарника, даже если release archive его не сохранил.
- Backend требует router bearer token; изменяющие endpoints дополнительно требуют Origin, совпадающий с Host и портом. Полноценное управление учётными записями, CSRF token и работа через reverse proxy не реализованы.
- Целевая среда подтверждена на роутере: KeeneticOS/Entware, AArch64, glibc 2.27.
- Тестовый AArch64-бинарник собран в CI с Entware dynamic loader (`/opt/lib/ld-linux-aarch64.so.1`) и проверен на устройстве на loopback-порту 18473: `/health`, отказ API без bearer-токена, read-only status с токеном и раздача frontend.
- В ходе перепроверки временный каталог `/tmp/xkeen-ui-readonly-2026101421` был найден после завершения сессии и удалён отдельно; порт 18473 не слушался. Вторая изолированная проверка использовала только loopback-порт 18474 и временный каталог; в конце каталог исчез, порт закрыт. Найденные штатные процессы не затрагивались. Её HTTP-коды не попали в сохранённый вывод, поэтому новые endpoint-журналы считаются проверенными CI, не роутером.
- Основной JS чанк интерфейса сокращён примерно с 528 КБ до 65 КБ: CodeMirror и конфигурационный редактор загружаются динамически только при открытии вкладки конфигурации.
- Репозиторий опубликован на GitHub. README отсутствует по просьбе пользователя. Стабильный v0.2.2 опубликован с ARM64 архивом и SHA256SUMS; пакет собран AArch64 CI из commit `2162ffb`. Этот архив содержал `xkeen-ui` без executable-бита, из-за чего меню ошибочно сообщало, что бинарник отсутствует; текущий bootstrap исправляет права после проверки SHA-256. Во время проверки `/releases/latest/download` вернул архив предыдущего релиза из-за устаревшего redirect-кэша; `install.sh` теперь берёт стабильный tag через GitHub API и скачивает файлы по tag URL. Порт по умолчанию — 1001.
- Shell bootstrap в CI проходит `sh -n` и ShellCheck. Rust installer содержит unit-тесты и отдельный изолированный CI сценарий install → auth/static check → update → stop/remove. Установка на пользовательском роутере не выполнялась.
- Последний опубликованный исходный commit: TypeScript — 130 835 байт, Rust — 108 345 байт, Shell — 5 245 байт (приблизительно 53.5% / 44.3% / 2.1% по GitHub Languages API). TypeScript пока ниже желаемых 55–60%, Rust выше ориентира 37–38%; показатели не подгоняются пустым кодом. Рабочий runtime не содержит ручного HTML-макета; Vite генерирует минимальный `index.html` как оболочку браузера.

## Среда

- Доступны Git, GitHub CLI, Node.js и pnpm workspace runtime.
- В текущем Windows workspace `cargo`, `rustfmt` и `shellcheck` не установлены. Rust, shell и AArch64 проверки следует считать подтверждёнными только после прохождения Linux CI.
- CI `38618811134` для `2162ffb` прошёл полностью: frontend (typecheck/60 tests/build), Rust (fmt/tests/build и изолированный installer lifecycle), installer (`sh -n`/ShellCheck) и AArch64 cross-build. Локальный Rust test/build на Windows не запускается из-за отсутствующего MSVC linker.
- Аудит структуры и исходников двух референсов собран в `docs/REFERENCE_AUDIT.md`; на устройстве проверена только read-only связность backend и выдача UI.

## Следующие шаги

1. Дождаться полного Rust fmt/test/build и AArch64 CI для текущего PR.
2. Установить обновление XKeen UI через панель, не меняя установленное ядро Mihomo и его источник; проверить статус службы и read-only DNS API.
3. Не включать DNS handoff во время smoke-проверки. Статические IPv6 DNS сохраняются в Keenetic и могут обходить Mihomo; DoH/DoT и фильтр контента не управляются.
4. После успешной проверки опубликовать стабильный релиз с AArch64 архивом и SHA256SUMS.
