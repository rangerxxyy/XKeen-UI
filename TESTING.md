# Проверка XKeen UI 0.2.0

## Frontend

Из каталога проекта:

```powershell
pnpm install
pnpm typecheck
pnpm test
pnpm build
```

`src/core-releases.test.ts` проверяет нормализацию URL форков, отказ для чужих host/path/credentials, выбор ожидаемых Xray/Mihomo архивов, валидацию данных GitHub, безопасные внешние ссылки, HTTP-ошибки и ограничение размера ответа.

Открой Vite dev URL, обычно `http://localhost:5173`. Проверь навигацию, настройки, состояние API при отключённом backend, responsive layout на ширине 375 px и отсутствие обязательных CDN-запросов.

Нижний журнал отображает только выбранный источник и ограниченный хвост. Обновление не должно сбрасывать поисковый фильтр; полноэкранный режим закрывается повторным нажатием. Кнопка очистки очищает только отображаемую область. Для API-журнала проверить allowlist идентификаторов, отказ для traversal, размер ответа до 256 KiB, ограничение 1000 строк и редактирование чувствительных значений; строки вставляются через `textContent`.

В ⚙ → «Источники ядер» проверь загрузку URL, нормализацию/сохранение двух отдельных репозиториев, сообщения об ошибке при неизвестном API и ограничения URL ровно корнем репозитория. В simulation изменения живут только до перезапуска backend. Путь бинарника при этой настройке не меняется.

В конфигурации переключи все вкладки `config`, `ip_exclude`, `port_exclude`, `port_proxying`, `xkeen`, `Xray JSON`, `Xray JSONC`: у каждой должен оставаться собственный черновик при переключении, а скачивание должно использовать имя активного файла. YAML-проверка/форматирование доступны только на вкладке `config`, JSON/JSONC проверяются и форматируются с сохранением комментариев JSONC; вкладки списков работают как локальный текст. Перезагрузка страницы в этой же вкладке браузера должна сохранять черновики в session storage.

Меню «Утилиты» содержит только действующие команды. Проверить выбор Mihomo YAML и Xray JSON-фрагмента, отказ при недоступном/некорректном каталоге, ограничение источника закреплённой ревизией, подтверждение замены непустого черновика, undo и экспорт по формату активной вкладки.

Для локального frontend проверяй selectors и connections в режиме без Mihomo: показываются корректные состояния недоступности, а не фиктивные данные. В connections проверь фильтрацию, отключённые действия при пустом списке и подтверждения перед закрытием. Отменённый `window.confirm` не должен вызывать DELETE.

Проверь DNS lookup с mock API: submit кодирует имя и тип как query-параметры, второй запрос отменяет первый, переход из DNS отменяет запрос, ответы и ошибки не превращаются в фиктивные записи. Роутерные DNS settings этой формой не меняются.

## Rust API

```powershell
cd backend
$env:XKEEN_MODE = 'simulation'
$env:XKEEN_PORT = '1001'
cargo test
cargo run
```

В другом PowerShell:

```powershell
Invoke-RestMethod http://localhost:1001/health
Invoke-RestMethod http://localhost:1001/api/v1/status | ConvertTo-Json -Depth 5
```

В simulation mode состояния служб должны быть `unknown`; режим не должен обращаться к реальным службам и конфигурациям. Дополнительно проверить отсутствие токена: simulation API должен работать без него; router mode должен завершаться с сообщением об обязательном `XKEEN_TOKEN`; корректный и некорректный bearer key должны давать HTTP 200 и HTTP 401 соответственно.

Изменяющие Mihomo API должны отклонять отсутствующий/чужой `Origin`, несовпадающий порт и неверный bearer token. Проверки закрытия одного соединения используют mock HTTP Mihomo API: некорректный или уже неактивный ID обязан отклоняться до DELETE; допустимый ID может посылать DELETE только в mock. Тесты не должны закрывать соединения на пользовательском роутере.

`GET /api/v1/mihomo/dns/query?name=example.com&type=A` требует router bearer token и допускает только корректное DNS-имя и whitelist типов RR. DNS lookup тестировать только через mock Mihomo API, пока отдельно не согласован read-only запрос к роутеру.

`GET /api/v1/settings/core-sources` использует тот же bearer token. `PUT` дополнительно требует same-origin `Origin`/`Host`; тесты проверяют только `https://github.com/{owner}/{repo}`-корень, ограничение host/path, atomic file replace в tempdir и права `0600` на Unix. Никогда не направлять settings persistence tests в `/opt/etc` тестового или пользовательского роутера.

## Роутер: безопасная read-only проверка

Задача `installer` в CI также запускает `sh tests/installer-proxy-priority.sh`: тест устанавливает mock-пакет через прокси, проверяет путь `releases/latest/download`, закреплённый tag и SHA-256.

На пользовательском KeeneticOS/Entware AArch64 с glibc 2.27 проверено:

- test binary собран с dynamic loader из `/opt/lib`;
- отдельный процесс запускался с `XKEEN_BIND=127.0.0.1` на временном порту 18473;
- ранее зафиксированные проверки `/health` (200), API без токена (401), авторизованного статуса и выдачи frontend прошли;
- при повторной сверке оставшийся временный каталог был удалён вручную после подтверждения, что порт 18473 не слушался. Повторную проверку API журнала следует считать незавершённой;
- процесс панели XKeen UI, службы Mihomo/XKeen, конфигурации и текущие утилиты на роутере не изменялись.

Установщик, создание init-службы и управляющие операции на роутере не запускались. DNS lookup, runtime-действия для Mihomo/Xray, маршрутов и конфигурации остаются вне этой проверки. Перед установкой на устройство подготовить точный план и обратимый rollback; выпускать команду установки только после проверки опубликованного архива и checksum.

В CI установщик отдельно прогоняется на временном каталоге Linux runner: install, проверка frontend assets, отказ API без токена, авторизованный status, права `0600`, сохранение настроек Mihomo, update, остановка службы и remove с сохранением конфигурации и резервной копии. Этот сценарий не подключается к пользовательскому роутеру.
