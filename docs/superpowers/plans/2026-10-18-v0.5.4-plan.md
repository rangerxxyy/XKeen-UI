# XKeen UI v0.5.4 Implementation Plan

> **For agentic workers:** Execute this approved user-specified release plan task-by-task. Keep each feature test-first and commit coherent increments.

**Goal:** deliver a tested and published XKeen UI v0.5.4 addressing the supplied P0–P3 defect/design list.

**Architecture:** retain the current TypeScript/Vite frontend and Rust/Axum backend. Trace each P0 path from UI through API to the actual router/config target; compare matching upstream `zxc-rv` components before changing behavior. Make focused, regression-tested changes and use CI’s ARM64 build as the release artifact.

**Tech Stack:** TypeScript, Vitest, Vite, Rust, Axum, GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-10-18-v0.5.4-product-design.md`

## Global Constraints

- Release version is exactly `0.5.4` in frontend, backend, package and release metadata.
- Work from latest v0.5.3 in branch `codex/v0.5.4`; do not rewrite prior release tags.
- Preserve current user/router configs; stage and roll back core/config writes safely.
- Runtime performance must suit low-resource routers; CSS motion uses transform/opacity and honors reduced motion.
- Never claim real Keenetic validation unless performed.
- Publish tag `v0.5.4` and checksum-verified AArch64 package only after all required CI jobs pass.

## Review Focus

- RAM values at exact-MB boundaries and non-MB byte totals; assert router source and formatting.
- Slow, rejected, or stale selector responses; assert UI responsiveness and correct final selected node.
- DNS request re-entry and failed/stale status; assert no duplicate fetch and explicit refresh behavior.
- Xray repo variants, ARM64 asset names, missing/empty assets; assert compatible releases appear or actionable errors.
- Config save/apply failures and utility write failures; assert original file is restored or error identifies the actual target.
