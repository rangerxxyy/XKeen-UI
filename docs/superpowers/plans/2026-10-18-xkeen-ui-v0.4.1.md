# XKeen UI v0.4.1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Выпустить v0.4.1 с изменениями после v0.4.0, завершить пояснения DNS по скриншоту и подтвердить артефакт для Linux AArch64.

**Architecture:** Сначала завершить DNS-представление и тесты без изменения сетевой логики, затем привести документацию и версии к фактическому состоянию. После зелёного CI получить артефакт из точного проверенного коммита, проверить его контрольную сумму и опубликовать релиз.

**Tech Stack:** TypeScript, Vitest, CSS, Rust/Cargo CI, GitHub Actions, GitHub Releases.

**Spec:** `docs/superpowers/specs/2026-10-18-xkeen-ui-v0.4.1-release-design.md`

## Global Constraints

- Не менять DNS, маршруты, firewall, ядра или системную конфигурацию пользовательского роутера для проверки релиза.
- Не заявлять о тестировании на реальном роутере и о полной совместимости со всеми функциями zxc-rv.
- Выпустить v0.4.1 в текущей последовательности версий 0.x.
- Использовать upstream SHA `4ffd568` и релиз `v1.3.8` как срез для аудита.
- Проверять архив только после прохождения CI для того же коммита, из которого он собран.

## Review Focus

- Подсказки не обрезаются границами DNS-карточек или прокручиваемого контейнера; тест: DOM содержит подсказку, визуальная проверка desktop/mobile подтверждает её отображение.
- Значки пояснений доступны клавиатурой и вспомогательным технологиям; тест: `tabindex="0"`, `aria-label`, hover/focus selectors.
- Текст статуса и адреса роутера экранируются и не попадают в HTML как разметка; тест: значение со `<` и `&` остаётся текстом.
- Светлая и тёмная темы сохраняют контраст значка и подсказки; проверка обеих тем в браузере.
- Подсказки сообщают реальные ограничения DNS (включая IPv6/DoH/DoT обходы и разницу режимов), не обещая перехват всего трафика; тест: содержимое подсказок и предупреждений.

### Task 1: Завершить подсказки раздела DNS

**Files:**
- Modify: `src/dns-view.ts`
- Test: `src/dns-view.test.ts`
- Modify: `src/style.css` и/или `src/ui-polish.css`

**Interfaces:**
- `renderDns(...)` остаётся публичным рендерером DNS-раздела.
- `dnsInfo(description: string): string` остаётся единым способом вывести фокусируемый значок пояснения с экранированным текстом.

- [ ] Добавить тест, проверяющий наличие отдельного информативного значка у каждого DNS-поля, параметра диагностики и строки статуса; проверить уникальное соответствие короткого английского названия и русской подсказки.
- [ ] Запустить `pnpm test -- --run src/dns-view.test.ts`; убедиться, что тест падает из-за отсутствующих подсказок.
- [ ] Добавить пояснения к `DNS Override`, `DNS Mihomo`, `Port 53`, `Router DNS Servers`, переключателю управления DNS, `Domain or IP` и `Record Type`; сохранить уже существующие подсказки к Enhanced Mode и всем DNS resolver полям.
- [ ] Обеспечить отображение текста при наведении и клавиатурном фокусе на значке `i`; сохранить `title`, `aria-label`, `tabindex` и HTML-экранирование.
- [ ] Добавить CSS для tooltip в тёмной и светлой темах с адаптацией к узкому экрану и без обрезания внутри DNS workspace.
- [ ] Повторно выполнить `pnpm test -- --run src/dns-view.test.ts`; тест должен пройти.
- [ ] Выполнить `pnpm test`, `pnpm typecheck`, `pnpm build` и осмотреть обе темы на desktop и узком viewport.

### Task 3: Проверить сборки и опубликовать v0.4.1

**Files/Artifacts:**
- Inputs: exact merged release commit and its GitHub Actions run.
- Outputs: `xkeen-ui-linux-aarch64.tar.gz`, `SHA256SUMS`, GitHub Release `v0.4.1`.

**Interfaces:**
- CI workflow `.github/workflows/ci.yml` produces the AArch64 archive and checksum as the `release-aarch64` artifact.
- Release installation remains through the existing checksum-verifying installer.

- [ ] Run full GitHub CI on the release commit; require frontend, backend, installer, and router-aarch64 jobs to pass.
- [ ] Download the `release-aarch64` artifact from that exact run; verify the manifest and confirm the archive contains the executable and web assets.
- [ ] Publish tag `v0.4.1` with `docs/release-notes-v0.4.1.md`, archive, and manifest.
- [ ] Download both public assets again and verify the archive SHA-256 matches the published manifest; check release tag, asset names, sizes and non-draft status.
- [ ] Report the release URL, commit, CI run, verified checksum, completed tests, and the unverified live-router limitation.
