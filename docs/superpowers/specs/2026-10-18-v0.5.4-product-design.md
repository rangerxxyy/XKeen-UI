# XKeen UI v0.5.4 Product Design and Acceptance Brief

**Goal:** ship a verified v0.5.4 release for Keenetic routers that closes the reported functional defects first, then aligns the interface with the local/online `zxc-rv/XKeen-UI` reference and the user screenshots.

**Audience and constraints:** owners of low-resource Keenetic routers (Entware, ARM/MIPS). Keep install/update recoverable, preserve existing config data, avoid heavyweight animation/CPU work, keep keyboard/touch access, and never expose configuration secrets in logs.

## Binding priorities

P0: correct reported RAM source/rounding; reduce selector switch latency; avoid unnecessary DNS status refetch; start config files in read-only mode; fix Xray release discovery; verify utility writes reach their actual target. Every P0 gets a regression test or reproducible isolated integration check.

P1: connections layout/icon reuse and readability; proxy/subscription behavior; DNS status/card order and DNS warning confirmation; config grouping and enabled/disabled save/apply ordering; core management and release flows; utility AmneziaWG/links/backups order.

P2: header/nav order and sizing; accessible status pulse; selector ping/close controls; consistent typography, gear icon, theme tokens, and lightweight transitions.

P3: responsive and keyboard smoke pass, no layout shift, human-readable failures, final visual comparison to all supplied screenshots and the upstream reference.

## Required behaviors

- Main navigation follows upstream section order and has distinct outlined icon tabs; logo is slightly larger without breaking narrow layouts.
- RAM uses the authoritative device total and correct unit conversion/rounding. Running indicator gently pulses about every 2 seconds without going fully dark and respects `prefers-reduced-motion`.
- Connections reuse the same service icon asset/component as selectors, with clearer route/service labels, grouping/status/host/source/traffic/time, aligned arrows and touch-safe close controls.
- Selector choice reaches Mihomo quickly without blocking UI; ping appears bright/readable at the far right of each node card; close controls are consistent.
- DNS status is reused while valid and refreshed on demand/meaningful state change. Remove the router DNS item; status is compact; management is item 4. Remove card-only backgrounds. Expanding DNS text fields must not hide sibling settings. Mihomo DNS transfer warning appears only at opt-in confirmation.
- Config files begin in view-only mode until explicit activation. Separate `config` from other file tabs. On changed YAML, Apply (green) is left of Save (blue); both are disabled/quiet when unchanged. Keep utilities/actions visible and page scrolling natural.
- Xray release listing must detect compatible ARM64 archives from configured GitHub sources. Mihomo/Xray installer dialogs share release list/progress/error patterns and core management button states.
- Proxy/subscription flow parses input, persists/applies settings, and visibly exposes imported proxies. AmneziaWG import remains available. Utilities links are complete and backups (if functional) are last.
- Apply a compact shared design system and only low-cost transform/opacity animation; retain contrast, focus, 44px mobile targets, dark/light themes, monospace configs/logs.

## Reference and validation

The upstream `zxc-rv/XKeen-UI` code at the verified commit and matching screenshots are the reference for behavior and structure; keep this project's dark visual language. Validate frontend tests, typecheck, production build, Rust fmt/tests/build, installer checks, and AArch64 CI artifacts. Smoke test selectors, connections, DNS, config, core releases, utilities, and proxy subscription. Do not claim real-router validation unless actually run on a router.
