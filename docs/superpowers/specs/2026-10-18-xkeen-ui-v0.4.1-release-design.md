# План выпуска XKeen UI v0.4.1

## Цель

Подготовить проверенный выпуск с изменениями, влитыми после v0.4.0, точно описать возможности и известные ограничения и опубликовать только те артефакты, которые собраны из проверенного коммита выпуска.

## Требования и источники

- Текущая основная ветка — `c4943fa` (`Align journal, templates, and DNS UX with reference (#38)`). Публичный v0.4.0 вышел раньше PR #37 и PR #38, поэтому его бинарные файлы не содержат эти изменения.
- Требования пользователя для этого этапа заданы сообщениями и скриншотами: убрать паузу журнала; сохранить поведение живого журнала по образцу zxc-rv; показывать соответствующие активному ядру шаблоны Mihomo/Xray и корректно импортировать их; убрать ручные действия проверки, форматирования и скачивания черновика; улучшить раздел DNS, использовать английские названия параметров и доступные пояснения для `redir-host` и `fake-ip`.
- PR #38 реализует эти требования, включает локальные копии каталога шаблонов из `zxc-rv/assets` с закреплённой ревизией и прошёл 214 frontend-тестов, а также проверки frontend, backend, установщика и сборки AArch64.
- Для сравнения с zxc-rv зафиксированы `main` коммит `4ffd568` и последний релиз `v1.3.8` по состоянию на 18 октября 2026 года. Сравниваются функции и сценарии; исходный код и интерфейс upstream не копируются.
- Отдельный файл технического задания в рабочей папке не найден. Это нужно указать как ограничение аудита; нельзя приписывать пользователю требования, обнаруженные только в коде или документации upstream.

## Объём релиза

- Выпустить следующий patch-релиз v0.4.1, сохранив используемую в репозитории последовательность версий 0.x.
- Включить уже влитые улучшения первой загрузки из PR #37, а также журнал, шаблоны, утилиты редактора и DNS из PR #38.
- Обновить аудит v0.4, карту возможностей, статус проекта и заметки к выпуску так, чтобы они соответствовали текущей основной ветке и выбранному срезу zxc-rv. Отсутствующие и непроверенные функции явно обозначить.
- Собрать архив выпуска из конкретного коммита, прошедшего CI; сформировать `SHA256SUMS`, скачать опубликованные артефакты и проверить архив по манифесту, прежде чем считать выпуск подтверждённым.
- При подготовке релиза не добавлять новые действия, меняющие состояние роутера, и не проводить испытания на пользовательском роутере. Указать, что проверка на реальном роутере не выполнена.

## Безопасность и отложенные функции

В этот patch-релиз не входят: сканирование Geo-баз, полный тест маршрутов, предпросмотр HTTP-подписок, конфигурация нескольких роутеров через плагины и полноценная система аккаунтов/сессий. Для них нужны отдельные проекты, проверки и ограничения операций. Управление DNS/content filter ограничено существующими защищёнными сценариями; нельзя заявлять о полном восстановлении DoH/DoT и фильтрации контента. Панель нельзя выставлять в публичный интернет без VPN или авторизованного шлюза.

## Условия проверки

1. Аудит документации соответствует текущей основной ветке и содержит SHA upstream-коммита и номер релиза, использованных для сравнения.
2. Для точного коммита выпуска проходят frontend-тесты, typecheck/build, форматирование и тесты backend, release build и lifecycle-тесты, проверки установщика и AArch64 cross-build.
3. Архив собран для Linux AArch64; контрольная сумма в `SHA256SUMS` совпадает с суммой заново скачанного архива.
4. Заметки к выпуску не заявляют проверку на пользовательском роутере, полного соответствия upstream или поддержки отложенных функций.

## За рамками

Изменение DNS, маршрутов, firewall, ядер или системной конфигурации роутера при проверке выпуска; добавление несвязанных функций; изменение лицензии; незаметный переход с принятой схемы версии на v4.0.0.
