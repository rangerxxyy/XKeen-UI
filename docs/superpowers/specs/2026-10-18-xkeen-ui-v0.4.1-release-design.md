# XKeen UI v0.4.1 Release Design

## Purpose

Prepare a verified follow-up release that includes the UI improvements merged after v0.4.0, gives users accurate release notes and known limitations, and ships only artifacts built from the verified release commit.

## Requirements and sources

- The current main branch is `c4943fa` (`Align journal, templates, and DNS UX with reference (#38)`). The preceding release v0.4.0 was published before PR #37 and PR #38, so its binaries do not contain those changes.
- The user's direct requirements and screenshots are the product requirements for this pass: remove journal pause; keep live journal behavior aligned with zxc-rv; offer the core-specific Mihomo/Xray template catalog and import flow; remove manual validate/format/draft-download menu actions; improve the DNS workspace with English setting names and accessible explanations for `redir-host` and `fake-ip`.
- PR #38 implements those requirements, bundles the catalog from `zxc-rv/assets` at a pinned revision, and passes 214 frontend tests plus frontend, backend, installer, and AArch64 CI.
- The zxc-rv comparison baseline is current `main` commit `4ffd568` and latest release `v1.3.8` as observed on 2026-10-18. Use its capabilities and workflows as comparison evidence; do not copy source code or its UI.
- No standalone requirements document was found in the task workspace. Record this as an audit limitation; do not invent requirements that appear only in upstream documentation or code.

## Release scope

- Publish the next patch version, v0.4.1, preserving the repository's current 0.x semantic-version sequence.
- Include the already merged PR #37 first-load stability work and PR #38 journal, templates, editor utility, and DNS improvements.
- Update the v0.4 audit, functionality map, project status, and release notes to match current main and the zxc-rv baseline. Clearly label features that are absent or unverified.
- Build the release archive from the exact green release commit, create `SHA256SUMS`, download the published assets, and verify the archive against the manifest before claiming release completion.
- Do not add new router-mutating behavior during release packaging. Do not test a live user router. Report that runtime router validation is still outstanding.

## Safety and deferred capabilities

The following capabilities remain outside this patch release because they need their own designs, tests, and operational constraints: Geo database scan, full route tester, HTTP subscription preview, plugin-based multi-router configuration, and comprehensive account/session authentication. DNS/content-filter operations remain limited to the existing guarded flows; do not claim complete DoH/DoT/content-filter restoration. Do not expose the management panel publicly without an authenticated gateway or VPN.

## Verification gates

1. The documentation audit matches current main and identifies the upstream SHA/release used for comparison.
2. Frontend tests, typecheck/build, backend formatting/tests/release build/lifecycle tests, installer checks, and AArch64 cross-build all pass for the exact release commit.
3. The release archive target is Linux AArch64; its `SHA256SUMS` matches a fresh download byte-for-byte.
4. Release notes do not imply live-router verification, full upstream feature parity, or support for deferred features.

## Out of scope

Changing the router's DNS, routing, firewall, core, or system configuration as part of release validation; introducing unrelated features; changing licensing; or silently changing the version scheme to v4.0.0.
